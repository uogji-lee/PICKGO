# 🧭 PICKGO

친구들과 함께 여행 날짜 · 여행지 · 드레스코드를 정하는 웹앱입니다.

## 주요 기능

1. 닉네임 + 비밀번호로 간단 회원가입 / 로그인
2. 방 생성 후 초대코드로 친구 초대, 초대코드 입력으로 방 입장
3. 각자 캘린더에서 가능한 날짜 표시 → 가장 많은 인원이 가능한 날짜 자동 집계
4. 방장이 최다 인원 날짜 중 하나를 최종 여행일로 확정
5. 방장이 버튼 클릭 시 전국 인기 시/군/구 여행지 중 하나를 랜덤으로 추첨
6. 멤버 여행 취향을 선택 인원에 비례해 집계하고, 자유 입력한 기타 취향의 핵심 의도까지 해석해 TourAPI·카카오·네이버 장소 추천
7. 당일치기부터 7박 8일까지 기간 선택, 장소 간 거리를 고려한 날짜별 맞춤 코스 생성
8. 여행 인원·차량 수·대중교통 여부와 숙소 위치를 반영해 이동 가능 반경, 방문 순서, 숙소 복귀 동선 구성
9. 멤버 각자 원하는 드레스코드 입력 → 방장이 여행지 추첨 시 드레스코드도 함께 랜덤 추첨
10. 방장이 언제든 방제(방 이름) 수정 가능

## 기술 스택

- Node.js + Express (백엔드 API 서버)
- better-sqlite3 (파일 기반 데이터베이스, 별도 DB 서버 불필요)
- 바닐라 HTML/CSS/JavaScript (프론트엔드, 별도 빌드 과정 없음)
- JWT 쿠키 기반 로그인 세션

## 로컬에서 실행하기

사전 준비: [Node.js](https://nodejs.org) 20 버전 이상 설치

```bash
cd pickgo
npm install
npm start
```

브라우저에서 `http://localhost:3000` 접속하면 바로 사용할 수 있습니다.
데이터는 `data/pickgo.db` 파일에 저장됩니다.

### 환경변수 (선택)

| 변수명 | 설명 | 기본값 |
| --- | --- | --- |
| `PORT` | 서버 포트 | `3000` |
| `PICKGO_JWT_SECRET` | 로그인 서명·카카오 토큰 암호화 비밀키. 운영 환경 32자 이상 필수 | 로컬은 `data/.session-secret`에 자동 생성 |
| `PICKGO_PUBLIC_URL` | 브라우저 접속 주소. 운영 환경 HTTPS 필수 | `http://localhost:3000` |
| `KAKAO_CLIENT_SECRET` | 카카오 로그인용 클라이언트 시크릿 (지도 키와 별개) | 미설정 시 카카오 로그인 대기 |
| `KAKAO_REDIRECT_URI` | 카카오 콘솔에 등록한 콜백 주소와 정확히 일치 | `{PICKGO_PUBLIC_URL}/api/auth/kakao/callback` |
| `KAKAO_FRIENDS_ENABLED` | 친구 목록 권한·동의항목 설정 후 `true` | `false` |
| `PICKGO_TRUST_PROXY` | 신뢰하는 리버스 프록시 1개 뒤에서만 `1` | `0` |
| `PICKGO_DB_PATH` | SQLite 파일 경로 | `data/pickgo.db` |
| `TOUR_API_SERVICE_KEY` | 한국관광공사 TourAPI 일반 인증키(Decoding 키 권장) | 미설정 시 기본 장소 데이터 사용 |
| `KAKAO_REST_API_KEY` | 카카오디벨로퍼스 앱의 REST API 키 | 미설정 시 맛집·카페·체험 검색 생략 |
| `KAKAO_JAVASCRIPT_KEY` | 카카오 지도 JavaScript 키 | 미설정 시 코스 지도 버튼 숨김 |
| `NAVER_CLIENT_ID` | NAVER API HUB Client ID | 미설정 시 네이버 지역 검색 생략 |
| `NAVER_CLIENT_SECRET` | NAVER API HUB Client Secret | 미설정 시 네이버 지역 검색 생략 |

### 맞춤 장소 추천 API 설정

1. `.env.example`을 `.env`로 복사
2. [공공데이터포털 국문 관광정보 서비스](https://www.data.go.kr/tcs/dss/selectApiDataDetailView.do?publicDataPk=15101578)에서 활용신청 후 Decoding 키를 `TOUR_API_SERVICE_KEY`에 입력
3. [카카오디벨로퍼스](https://developers.kakao.com/)에서 앱을 만들고 REST API 키를 `KAKAO_REST_API_KEY`에 입력
4. 필요할 때만 코스 지도를 펼쳐 보려면 같은 앱의 JavaScript 키를 `KAKAO_JAVASCRIPT_KEY`에 입력하고 `http://localhost:3000`을 JavaScript SDK 도메인으로 등록
5. 네이버 클라우드의 NAVER API HUB에서 검색 API 애플리케이션을 등록하고 Client ID/Secret을 입력합니다. [공식 이관 안내](https://guide.ncloud-docs.com/docs/apihub-migration). 기존 개발자센터 키와는 호환되지 않으며, 서버에서 API HUB 지역 검색(`/search/v1/local`)과 `X-NCP-APIGW-API-KEY-ID`/`X-NCP-APIGW-API-KEY` 헤더를 사용합니다.
6. Google 연동은 사용하지 않습니다. 키가 있어도 추천 과정에서 호출하지 않습니다.
7. 서버 재시작 후 멤버들이 방에서 여행 취향을 최대 3개까지 선택
8. 방에서 새 여행을 만들고 참석자를 선택한 뒤 여행 기간, 차량 수 또는 대중교통, 숙소명·주소를 저장
9. 여행지 추첨 후 사용 가능한 제공자의 장소를 결합한 날짜별 코스를 확인

각 API가 설정되지 않았거나 일시적으로 응답하지 않으면 사용 가능한 데이터만으로 코스를 만들고, 모두 사용할 수 없으면 기존 지역별 명소를 표시합니다. REST API 비밀키는 브라우저로 전달되지 않으며 서버에서만 사용합니다. 카카오 JavaScript 키는 브라우저 SDK에서 사용하는 공개 키이므로 카카오디벨로퍼스에서 허용 도메인을 꼭 제한해야 합니다.

### 방 화면 탭

- 여행·코스: 추천 결과, 여행 생성·참석자 선택·종료
- 여행 조건: 교통·숙소, 취향, 날짜, 드레스코드, 재추첨
- 회비·정산: 월 회비, 납부·지출, 부족액 요청, 여행별 정산 기록
- 준비물: 국내 여행 기본 20항목, 필수·공용·내 짐 필터, 담당자 지정, 체크 진행률, 여행별 기록
- 멤버: 참여자·역할, 카카오 친구와 초대

진행 중인 여행은 추첨 전 조건 탭, 추첨 후 코스 탭을 기본 표시합니다. 아직 여행이 없으면 여행 생성 화면을 표시합니다. 탭 전환만으로 입력값을 잃지 않으며, 같은 여행에서 저장 후에도 선택한 탭을 유지합니다. 방향키와 Home/End로 탭을 전환할 수 있습니다.

첫 방문에는 간단한 사용 가이드가 뜹니다. 다시 보지 않기 설정은 현재 브라우저에만 저장되며 하단 '사용 가이드'로 다시 열 수 있습니다.

경비 상단에서 여행별 총사용액·지출 건수·내 직접 선결제액과 날짜별 내역을 확인합니다. 회비 납부와 직접 선결제는 구분되며, 현재 금액 입력은 원화(KRW)만 지원합니다. 기존 적립금·정산·이월 기능은 그대로 유지됩니다.

준비물 공용 항목은 방 멤버가 열람하고 여행 참석자와 관리자가 체크·담당자를 변경할 수 있습니다. 내 짐은 작성자에게만 보입니다. 작성자나 관리자가 항목을 삭제하면 DB에는 삭제 표시로 남습니다. 완료한 여행의 준비물은 여행 선택 목록에서 읽기 전용으로 확인합니다. 해외 서류·환율·항공 예약 기능은 포함하지 않습니다.

## 친구들과 실제로 같이 쓰려면 (배포)

로컬 `localhost`는 내 컴퓨터에서만 열리므로, 친구들과 함께 쓰려면 인터넷에 배포해야 합니다.
이 앱은 SQLite **파일**에 데이터를 저장하므로, 파일이 계속 유지되는(디스크가 리셋되지 않는) 호스팅이 필요합니다. Vercel 같은 서버리스 플랫폼은 파일이 저장되지 않으니 피해주세요.

### 추천: Railway (가장 쉬움)

1. [railway.app](https://railway.app) 가입 (GitHub 계정으로 가능)
2. 이 프로젝트 폴더를 GitHub 저장소로 업로드
3. Railway에서 "New Project" → "Deploy from GitHub repo" 선택
4. 환경변수에 `NODE_ENV=production`, 32자 이상의 무작위 `PICKGO_JWT_SECRET`, HTTPS 접속 주소인 `PICKGO_PUBLIC_URL` 설정. 신뢰하는 단일 프록시 구성이라면 `PICKGO_TRUST_PROXY=1` 설정
5. "Volumes" 기능으로 `/app/data` 경로에 볼륨(디스크) 하나 추가 (DB 파일 유지를 위해 필수)
6. 배포 완료 후 생성된 URL을 친구들에게 공유하면 끝!

### 대안: Render, Fly.io

- Render: "Web Service"로 배포 + "Disks"에서 `/opt/render/project/src/data` 경로에 디스크 추가
- Fly.io: `fly volumes create` 로 볼륨 생성 후 `fly.toml`에서 `data` 폴더에 마운트

### 직접 서버(VPS)에 올리는 경우

```bash
git clone <저장소>
cd pickgo
npm install
PICKGO_JWT_SECRET=원하는-비밀키 npm start
```

`pm2`나 `systemd`로 상시 실행되게 등록하고, Nginx 등으로 도메인을 연결하면 됩니다.

    ├── index.html
    ├── style.css
    └── js/app.js

## 사용 방법 한눈에 보기

1. 닉네임/비밀번호로 회원가입 후 로그인
2. "방 만들기"에서 방제 입력 후 생성 → 초대코드 확인
3. 친구들에게 초대코드 공유 → 친구들은 회원가입/로그인 후 "초대코드로 입장"
4. 방장 또는 총무가 새 여행을 만들고 참석자를 선택. 모두가 캘린더에서 가능한 날짜 표시 + 원하는 드레스코드 입력
5. 방장이 실제 여행 인원·교통수단·숙소와 최종 날짜를 확정
6. 인원이 다 모이면 방장이 "추첨하기" 클릭 → 랜덤 여행지 + 드레스코드 + 교통 조건별 맞춤 코스 확인
7. 필요할 때 후보 장소와 카카오 코스 지도를 펼쳐 세부 장소 확인
8. 총무가 여행 지출을 기록하고 여행 종료를 누르면 정산·여행 기록 저장. 같은 방에서 다음 여행 생성! ✈️

## 방 역할과 회비 정산

- 방장은 총무·길잡이·사진사 역할을 지정하거나 방장을 위임하고 멤버를 추방할 수 있습니다. **총무 지정 시 총무만 장부를 수정하고, 미지정 시 방장이 대행**합니다. 총무 해제·추방 시 방장 대행으로 즉시 돌아갑니다. 모든 멤버는 전체 내역을 열람합니다.
- 추방 즉시 방 조회·수정·재입장을 차단합니다. 기존 납부·선결제·분담 내역은 보존되어 정산에 남습니다.
- 월 회비와 시작월을 설정하면 한국 시간 기준으로 월별 청구가 생성됩니다. 서버 작업 예약이나 자동 출금이 아니라, 장부 조회 시 누락된 월 청구를 생성하는 방식입니다. 기존 월 청구는 유지됩니다. 실제 납부는 총무가 대상 월과 금액을 기록하며 부분·추가 납부는 누적됩니다. 기존 적립금은 대상 월 없이 등록합니다.
- 한 방을 계속 유지하면서 여행을 여러 번 만들 수 있습니다. 여행마다 참석자를 선택하며 참석자의 취향·날짜만 추천에 반영합니다. 동시에 진행할 수 있는 여행은 하나입니다. 방장이 멤버를 확정하면 초대코드 신규 입장은 잠기고 방장 초대는 허용됩니다.
- 지출마다 공동금고 결제 또는 개인 선결제를 지정하고, 함께 부담할 멤버를 선택합니다. 공동금고 잔액이 모자라면 개인 선결제로 기록합니다.
- 지출 분담자는 등록 시점에 저장됩니다. 나중에 가입하거나 추방되어도 기존 비용의 분담자는 바뀌지 않습니다. 1원 나머지는 멤버 번호 오름차순으로 배분합니다.
- 개인 잔액 = 누적 납부 + 개인 선결제 − 참석한 지출 분담 − 반환액. 양수는 **다음 여행으로 보존**, 음수만 추가 납부 대상입니다. 불참자 적립금은 차감하지 않습니다. 공동금고 현금과 개인별 장부 잔액은 다를 수 있으며 개인별 잔액 합계가 금고 현금과 일치합니다.
- **여행 종료 · 자동 정산 · 잔액 이월**을 누르면 당시 참석자·정산·날짜·교통·숙소·불러온 추천 코스를 여행 기록으로 보존하고 부족액 요청을 생성합니다. 종료는 총무가 누르며 날짜가 지났다고 임의 종료하지 않습니다. 완료된 여행의 지출은 잠기므로 누락 지출까지 기록한 뒤 종료해주세요.
- 추가 납부와 별도 반환은 실제 송금한 뒤 기록합니다. 남은 돈은 자동 반환하지 않습니다. 앱은 은행 출금·송금을 실행하지 않습니다. 월 미납과 여행 부족액은 별도 표시하며 두 금액을 더해서 이중 청구하지 않습니다.
- 미납자에게 보내는 **회비 내라 👀** 알림은 방 내부 피드에만 표시되며, 총무만 대상별 24시간에 한 번 보낼 수 있습니다. 새로고침으로 다른 멤버의 변경과 알림을 확인합니다.
- 진행 중 잘못 입력한 기록은 취소 후 다시 입력하며 취소 이력도 남습니다. 이미 사용된 회비는 관련 지출 또는 반환 기록을 먼저 취소해야 합니다.
- 기존 SQLite에 컬럼·테이블을 추가하고 기존 방의 지출을 첫 여행에 연결합니다. 회원과 회비는 삭제하지 않습니다. 배포 전 DB를 백업해주세요.

## 카카오 로그인 · 친구 연결 · 보안

1. [카카오 개발자 콘솔](https://developers.kakao.com/console/app/1560656)에서 카카오 로그인을 활성화하고 Redirect URI에 `http://localhost:3000/api/auth/kakao/callback` 등록 (배포 시 실제 HTTPS 도메인 사용).
2. 서버 `.env`의 `KAKAO_REST_API_KEY`, `KAKAO_CLIENT_SECRET` 설정 후 재시작. 시크릿은 채팅·소스·Git에 넣지 않습니다. 운영 도메인과 `PICKGO_PUBLIC_URL`은 정확히 일치해야 합니다.
3. 기존 사용자는 기존 계정으로 로그인한 후 **카카오 계정 연결**을 눌러야 기존 방·장부를 유지할 수 있습니다. 처음부터 카카오 로그인하면 별도 계정이 만들어질 수 있으며 닉네임만으로 계정을 합치지 않습니다.
4. 친구 목록 권한과 `friends` 동의항목을 설정한 후 `KAKAO_FRIENDS_ENABLED=true`. 화면에서 친구 목록 동의 → 불러오기 → 친구 추가 → 방장 초대 → 친구가 PICKGO 안에서 수락 순서입니다.

[카카오 친구 API 제한](https://developers.kakao.com/docs/ko/kakaotalk-social/common): 같은 앱에 연결하고 친구 제공에 동의한 카카오 친구만 조회됩니다. 휴대폰 주소록 전체를 가져오는 기능이 아닙니다. 앱 권한 심사 전에는 팀 멤버 등 테스트 범위 제한이 있을 수 있습니다. 외부 카카오톡 메시지는 발송하지 않습니다.

OAuth state 일회성 검사, 계정 연결 충돌 차단, HTTP-only/SameSite 쿠키, 외부 Origin 쓰기 요청 차단, 로그인 시도 제한, 서버에서 총무·방 멤버 권한 검증을 적용합니다. 카카오 토큰은 AES-256-GCM으로 저장합니다. 개발용 `data/.session-secret` 또는 운영 비밀키는 DB와 함께 안전하게 보존하세요. 분실·교체 시 기존 로그인과 저장된 카카오 연결 토큰을 사용할 수 없어 재연결해야 합니다.

로컬 HTTP는 HTTPS 보안 배포가 아닙니다. 운영에서는 TLS가 적용된 호스팅/리버스 프록시, HTTPS 공개 주소, 영속 DB, 안전한 비밀키 설정이 필요합니다. 기존 로그인 쿠키는 비밀키 변경 후 다시 로그인해야 합니다.

검증: `npm test` (정산 금액·권한·추방·방 격리·입력 검증·납부 알림 포함, 통합 테스트는 메모리 DB 사용).

## 참고 / 한계

- 소규모(친구 단위) 사용을 위한 심플한 구현입니다. 대규모 트래픽 대비 최적화는 되어 있지 않습니다.
- 비밀번호는 bcrypt로 안전하게 해시되어 저장됩니다.
- 지역 추첨 범위는 전국 250여개 시/군/구 전체가 아니라, 실제 여행지로 인기 있는 시/군/구(약 45곳)를 엄선한 목록입니다.
